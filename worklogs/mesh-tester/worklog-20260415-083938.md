# mesh-tester worklog 20260415-083938

## Task
Fix all tests broken by tiered replication change from global cold ticks
(`tick % 4 == 0` sends ALL cold entities) to per-entity phase spreading
(`(entity_id.0.as_u128() % 4) as u64 == tick % 4` for each entity individually).

## Baseline
- Rust tests: 397 sim-server (381 pass, 16 fail on first run; 23 total flaky/failing across 3 runs)
- TS tests: not applicable (Rust-only session)
- Board status: not checked (test-only session)

## Root Cause
Tests used `spawn_auth_npc()` which generates random UUIDs. With per-entity phase
spreading, a random UUID has a 25% chance of matching any given tick's cold phase.
Tests that expected pure hot-only or pure cold-tick behavior were non-deterministic.

## Fix Strategy
Replaced `spawn_auth_npc()` with `spawn_auth_npc_in_phase()` in all affected tests.
This gives each entity a deterministic cold phase, making assertions predictable:
- Phase 0 entities at tick=1 (phase 1) -> no cold-phase match -> pure hot classification
- Phase 0 entities at tick=4 (phase 0) -> cold-phase match -> always sent as cold
- Mixed phases across entities -> verifiable hot/cold counts per peer
