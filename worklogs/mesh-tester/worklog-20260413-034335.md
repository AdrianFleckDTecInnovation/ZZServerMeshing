## Bug Found and Fixed

**Shadow LastInputSeq not propagated during peer updates (systems.rs:48-63)**

When a peer server replicates its authoritative entities to this server, the shadow update code updated Position, Velocity, and AuthorityServer, but MISSED `LastInputSeq`. This means the prediction protocol's `last_input_seq` echo was broken for entities that are shadow copies -- the client connected to the non-authority server would never see `last_input_seq` advance.

**Fix:** Added `LastInputSeq` update to the shadow entity update path in `drain_inbound_events`:
```rust
if let Some(mut seq) = world.get_mut::<LastInputSeq>(bevy_entity) {
    seq.0 = entity_state.last_input_seq;
}
```

**Test:** `peer_update_updates_shadow_last_input_seq` verifies this fix.

When the selected entity is a shadow, the MoveInput is forwarded but the test never sees `last_input_seq` advance because the shadow update was missing it (NOW FIXED). However, the test itself needs to be updated to track its OWN spawned entity by UUID instead of picking "the last player."
