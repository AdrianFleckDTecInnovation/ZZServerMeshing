### Failure Analysis

**crash-recovery (FAIL):** The coordinator detected the S3 crash, but survivors did not adopt the orphaned entities within the 20s timeout. This is a known issue -- the recovery mechanism needs investigation at the sim-server level (coordinator sends RecoverEntities but servers may not be processing it properly, or the test may need to account for restart time since the test itself restarts S3 at the end).

**input-seq-echo (FAIL):** The test sends a MoveInput with seq=1 and expects last_input_seq=1 echoed back within 2s. The entity was on S1, the test client was on S1, so no forwarding needed. The server processes the input (velocity changes confirm this) but the binary protocol may not be echoing last_input_seq correctly on the boards. Likely a pre-existing issue.
