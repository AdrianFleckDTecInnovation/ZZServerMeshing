### CRITICAL FINDING: Heartbeat Timeout Bug Still Present

The coordinator journal (captured by systemd, not in coordinator.log) reveals the timeline:

```
05:07:48  WARN  S3 missed heartbeat -- marking as dead
05:08:13  WARN  S2 missed heartbeat -- marking as dead
05:08:33  WARN  S1 missed heartbeat -- marking as dead
```

All 3 servers were marked dead via heartbeat timeout during heavy rebalancing (transfers of 200-300 entities at a time). The 15s timeout was insufficient.

### Root Cause: Heartbeat Timeout Removes Servers With Live WebSocket Connections

The reconnection fix in coordinator_client.rs (loop with re-register) and the re-registration logic in registry.rs are both working as designed -- but they never trigger because the bug is elsewhere:

1. During heavy rebalancing, sim-servers are CPU-bound processing transfers
2. This delays their heartbeat responses past the 15s timeout
3. The coordinator calls `reg.unregister(sid)` -- removing the server from the HashMap
4. But the WebSocket connection is still alive -- the sim-server never detects a disconnect
5. The sim-server continues sending heartbeats, but `reg.heartbeat()` is a no-op because the server_id is no longer in the HashMap
6. The reconnection loop never fires because `ws_stream.next().await` never returns None

This is a different failure mode than the previous "connection lost" scenario. The WebSocket stays up, but the server is silently de-registered.

### Possible Fixes

1. **In `detect_dead_servers`**: instead of `reg.unregister(sid)`, close the WebSocket connection (drop `reply_tx`) so the sim-server detects the disconnect and re-registers
2. **In `reg.heartbeat()`**: if a server sends a heartbeat but isn't registered, log a warning and auto-re-register it (requires keeping the reply_tx available)
3. **Increase timeout further**: 30s or 60s to tolerate sustained heavy rebalancing
4. **Rate-limit rebalance**: don't issue multiple 300-entity rebalance directives within 5s -- give servers time to breathe

### Reconnection Fix Verification

The reconnection fix (coordinator_client.rs loop + registry.rs re-registration logic) was never tested because:
- No sim-server ever logged "Lost coordinator connection, will re-register"
- No coordinator ever logged "re-registering (old connection dead)"
- The WebSocket connections remained alive throughout

The fix is structurally correct but targets the wrong failure mode. The actual failure mode is heartbeat timeout with a live WebSocket, not a dropped WebSocket connection.
