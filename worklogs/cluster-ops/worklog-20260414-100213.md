### CRITICAL BUG: 30-Second Coordinator Reconnection Storm

The sim-server's `coordinator_client.rs` has a 30-second read timeout on the coordinator
WebSocket connection (line 72). The coordinator does NOT send periodic keepalives -- it only
sends messages on topology changes (PeerList, RebalanceDirective, RecoverEntities). Once the
cluster stabilizes with balanced entity counts, no messages flow from coordinator to servers.
After 30 seconds of silence, all servers timeout and reconnect.

Each reconnection cycle:
1. Server A times out, disconnects
2. Coordinator declares Server A "crashed", broadcasts RecoverEntities to survivors
3. Survivors promote Server A's shadow entities to authoritative (entity duplication)
4. Server A reconnects with its original entities (now duplicated on survivors)
5. Repeat every 30 seconds, entity count grows unboundedly

Evidence from coordinator log:
- 03:10:22: Initial registration (3 servers, clean)
- 03:10:54: S1+S2 crash+recovery (+32s, first timeout)
- 03:06:01: S1+S2 crash+recovery (from first deploy, same pattern)
- 03:06:33: S1+S2 crash+recovery (+32s again)
