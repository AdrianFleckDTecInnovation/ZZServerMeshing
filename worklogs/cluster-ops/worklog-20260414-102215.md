### Detailed Notes

**spatial-hotspot (FAIL):** Test code bug, not a server bug. The scenario accesses `metrics[i].phases.replication_ms.p95` but one of the server metrics objects returned from `getAllMetrics()` has `phases` undefined. The server metrics endpoint does include phases (verified manually). This is likely a timing issue in the test -- getAllMetrics fetches all 3 servers in parallel and one may not respond with phases if the metrics haven't accumulated yet (server was freshly restarted). The actual hotspot handling (200 entities in 50x50 area) worked fine -- entities were spawned and cleaned up correctly.

**authority-transfer (WARN):** After spawning 100 entities to S3 (creating imbalance), the coordinator didn't issue transfers within 30s. Distribution: S1:276 S2:235 S3:384. Imbalance ratio: 1.6x. The coordinator's rebalance threshold may require a higher ratio to trigger. By the end, distribution settled to S1:276 S2:263 S3:281 -- entity counts did shift (S2 gained 28, S3 lost 103), suggesting rebalance happened but the test didn't detect individual entity authority changes. This may be because entities gained by S2/S3 were from ongoing NPC spawning from earlier tests, not transfers.

**aoi-filtering (PASS -- key scenario):** Working correctly.
- Player at origin (0,0,0)
- 10 near NPCs spawned within AoI -- client saw 29 entities (19 baseline + 10 near)
