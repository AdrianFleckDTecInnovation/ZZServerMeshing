sending FRAME_ACK every tick. Result:
```
Full=285  Delta=4  Other=1  acks=290
```
Delta frames ARE flowing (4 out of ~289). The ratio is low because every
NPC moves every tick, so the 80% change-ratio heuristic fires on most ticks
and falls back to full. This is exactly the user's stated reason for
keeping delta: when stationary entities (inventory, dormant players) exist,
the ratio drops and deltas start compressing meaningfully.

## Issues Encountered

1. **ClientFrame enum vs Vec<u8>.** The restored HEAD snapshot.rs was
   written when `ClientFrame = Vec<u8>`. Batch 4 (WI-201) later changed it
   to an enum `ClientFrame { Binary(Vec<u8>), Text(String) }` for mid-
   session JSON text frames. I wrapped all three `try_send(frame)` sites
   with `ClientFrame::Binary(frame)`. The #[cfg(test)] `Deref for ClientFrame`
   impl lets the test helpers continue to index/slice into frames without
   unwrapping.

2. **register_from_event signatures had to merge Batch 6 AND Batch 4
   changes.** Post-revert, both `register_from_event` (test-only) and
   `register_from_event_with_migrating` (production) take `acked_tick`
   again — plus the Batch 4 `migrating_out` on the latter.

3. **Boards: stale binary lock.** First `./start-unoq.sh` attempt failed
   with "scp dest open 'mesh/sim-server': Failure" on all 3 boards. Root
   cause: the binary was read-only from a prior run with the dashboard's
   exec permissions. Fixed with `ssh unoq 'rm -f ~/mesh/sim-server'` on
   each board, then retried. Deploy succeeded.

4. **multi-client scene test fails on boards.** Pre-existing. The
   scenario's `fetch(/servers)` path throws because Node's default fetch
   doesn't accept self-signed certs; the catch-handler falls back to a
   localhost port-swap assumption that doesn't match the boards'
   distributed topology. Unrelated to this revert.
