### Issue 1: Two-Phase Authority Transfer (WI-001 through WI-008)

- `crates/shared/src/protocol.rs`: Added `PeerMessage::TransferAck { entity_id, tick }` variant with bincode roundtrip test
- `crates/sim-server/src/resources.rs`: Added `InboundTransferAck` struct and `transfer_acks: Vec<InboundTransferAck>` field to `InboundQueue`; added `started_tick: Option<u64>` to `DrainState`
- `crates/sim-server/src/components.rs`: Added `TransferOutbound` component with `target_server`, `target_addr`, `sent_tick`, `retry_count`, `serialized_msg` fields; added component query test
- `crates/sim-server/src/receiver.rs`: Added match arm for `PeerMessage::TransferAck` that pushes to `InboundQueue.transfer_acks`
- `crates/sim-server/src/game_loop.rs`: Added `transfer_acks` to Phase 1 inbound swap from async buffer to ECS
- `crates/sim-server/src/systems.rs`:
  - Added `send_transfer_ack` helper function (looks up source in PeerAddresses, serializes ACK, pushes to OutboundTransfers)
  - Modified `drain_inbound_events`: sends TransferAck after accepting transfers (promoted shadow, new entity, and duplicate cases)
  - Added `process_transfer_acks` system: drains ACKs, despawns entities with TransferOutbound on matching ACK
  - Added `process_transfer_timeouts` system: retries once at 500ms (10 ticks), then aborts (removes TransferOutbound, keeps Authoritative)
  - Added constants: `TRANSFER_TIMEOUT_TICKS = 10`, `TRANSFER_MAX_RETRIES = 1`, `DRAIN_TIMEOUT_TICKS = 600`
  - Modified `process_transfers`: inserts TransferOutbound + cloned serialized_msg instead of despawning; skips entities already in transfer
  - Modified `process_drain`: inserts TransferOutbound instead of despawning; checks both remaining non-outbound and pending outbound counts for completion; adds drain timeout at 30s
- `crates/sim-server/src/schedule.rs`: Inserted `process_transfer_acks` and `process_transfer_timeouts` between `drain_inbound_events` and `drain_client_events`
