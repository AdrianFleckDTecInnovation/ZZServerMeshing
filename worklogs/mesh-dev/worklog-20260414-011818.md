## Changes Made

### WI-020: Vec3 distance threshold
- `crates/sim-server/src/delta.rs`: Added `CHANGE_THRESHOLD_SQ` constant (0.0001 = 0.01^2). Replaced `vec3_changed` body from per-component `abs() > CHANGE_THRESHOLD` to `a.distance_squared(b) > CHANGE_THRESHOLD_SQ`. This treats diagonal movement uniformly -- an entity moving 0.008 on X and Z (total displacement 0.0113) is now correctly detected as a change, fixing audit finding #022.
- `crates/sim-server/src/delta.rs`: Added 3 tests: `diagonal_movement_above_threshold`, `diagonal_movement_below_threshold`, `change_threshold_sq_value`. All existing threshold tests pass unchanged (axis-aligned behavior identical).

### WI-021: Delta fallback heuristic
- `crates/sim-server/src/systems.rs`: Added `DELTA_FALLBACK_THRESHOLD: f32 = 0.80` constant. In `prepare_client_snapshot`, after computing the delta, checks if `updates.len() / entities.len() > 0.80`. If so, sends a full snapshot via `Arc::clone` instead of encoding a delta frame. Baseline is rebuilt from scratch (not incrementally updated). Fixes audit finding #027.
- `crates/sim-server/src/systems.rs`: Added 4 tests: `delta_fallback_all_entities_changed` (100% triggers fallback), `delta_fallback_below_threshold` (70% stays delta), `delta_fallback_at_boundary` (80% stays delta, strict >), `delta_fallback_just_above_boundary` (90% triggers fallback).
- `crates/sim-server/src/systems.rs`: Updated `per_client_delta_detects_entity_movement` test to use 3 entities (was 1). With the fallback heuristic, moving 1/1 entity = 100% change ratio, which triggers the fallback. Using 3 entities keeps the change ratio at 33% so the delta path is exercised.

### WI-022: Wire ACKs into baseline management
- `crates/sim-server/src/resources.rs`: Added `last_sent_tick: u64` field to `ClientHandle`, initialized to 0 in `register_from_event`. Added `ACK_STALE_TICKS: u64 = 40` constant (2 seconds at 20Hz). Removed `#[allow(dead_code)]` from `acked_tick` field since it is now read.
- `crates/sim-server/src/systems.rs`: In `prepare_client_snapshot`, reads `acked_tick` and checks for stale ACK: `last_sent_tick.saturating_sub(acked) > ACK_STALE_TICKS`. When stale, forces a full snapshot with a log message. Updates `last_sent_tick = tick.0` on every successful send (all 3 paths: full, fallback-full, delta). Fixes audit finding #021.
- `crates/sim-server/src/systems.rs`: Added helper `register_test_client_with_ack` that returns both receiver and acked_tick Arc. Added 6 tests: `ack_stale_forces_full_snapshot`, `ack_fresh_sends_delta`, `ack_stale_new_client_no_false_positive`, `ack_at_boundary_not_stale`, `last_sent_tick_updated_on_send`, `ack_stale_ticks_constant_value`.
- `crates/sim-server/src/systems.rs`: Updated `per_client_periodic_full_snapshot_at_interval` and `per_client_ticks_since_full_resets_on_full` tests to ACK each tick, preventing stale-ACK detection from interfering with periodic full snapshot testing.

### WI-023: ACK tick validation
- `crates/sim-server/src/network.rs`: Added monotonicity check to ACK parser in `handle_client`. ACK is only stored if `tick > 0` (rejects zero) and `tick > prev` (rejects non-advancing ACKs). Prevents stale/reordered ACKs from regressing the value. Fixes audit finding #025.
- `crates/sim-server/src/systems.rs`: In `prepare_client_snapshot`, clamped acked_tick with `.min(tick.0)` to prevent malicious clients from sending future ticks and bypassing stale-ACK detection.
- `crates/sim-server/src/network.rs`: Added helper functions `apply_ack_validation` and `make_ack_frame` for unit testing ACK validation logic. Added 3 tests: `ack_monotonicity_rejects_lower`, `ack_rejects_zero`, `ack_monotonicity_sequential`.
- `crates/sim-server/src/systems.rs`: Added `ack_clamp_to_server_tick` test verifying that u64::MAX ACK is clamped to current tick, and stale detection still works after clamp.
