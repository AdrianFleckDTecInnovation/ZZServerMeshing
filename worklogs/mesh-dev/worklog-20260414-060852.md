## Design Rationale

The three fixes address different failure modes:

1. **Yield points** fix the root cause: the game loop blocking the tokio runtime thread. `yield_now()` is zero-cost when no other tasks are waiting, and only actually suspends when the scheduler has pending work (like the heartbeat task). Two yield points per tick at 20Hz means the heartbeat task (1Hz) gets 40 chances per second to run.

2. **Activity events** fix the observation gap: even if the heartbeat task is delayed, the server is still sending other messages (Register on startup, responses to PeerList, etc.). Using these as liveness signals means the coordinator sees activity even when explicit heartbeats are late.

3. **30s timeout** fixes the margin: at 5000+ entities with heavy rebalancing, transient delays of 15+ seconds are possible during authority transfer storms. 30s gives 2x the margin of the previous 15s timeout while still detecting genuinely dead servers (process crash, network partition) within a reasonable window. The shadow stale timeout (15s/100 ticks) is independent and acceptable to exceed briefly.
