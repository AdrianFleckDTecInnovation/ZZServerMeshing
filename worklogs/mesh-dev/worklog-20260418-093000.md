### WI-221: Single-pass prepare_replication classifier

- `crates/sim-server/src/systems/replication.rs`: rewrote the three-
  branch logic as a single classifier. For each authoritative entity, walk
  each registered peer exactly once and decide hot / cold / bootstrap
  inclusion in one place. Pre-seed an empty entry in `per_peer` for every
  peer with shadows + valid bounds (preserves the pre-refactor invariant
  that downstream code can distinguish "peer known, nothing to send" from
  "peer unknown").
- All 42 replication tests continue to pass unchanged. The pre-seed was
  required to match the old contract that shadowed peers always appear in
  `per_peer` even when no entity matches the phase filter — tests
  (`peer_repl_peer_removed_not_in_per_peer`, `tiered_player_vs_npc_shadow`,
  `tiered_entity_just_outside_peer_aoi`, etc.) relied on
  `per_peer[&peer_id]` index-access not panicking.
- Behavior is equivalent: hot = near any player shadow in PEER_AOI_RADIUS;
  cold = phase-matched AND in PeerBounds; bootstrap = shadowless peers get
  phase-matched entities at 5Hz.

### WI-223: --coordinator-tls flag

Sim-server side:
- `crates/sim-server/Cargo.toml`: added `rustls-tls-webpki-roots` feature
  to tokio-tungstenite; added `rustls-pki-types` dependency.
- `crates/sim-server/src/main.rs`: added `--coordinator-tls` CLI flag
  (default false). When set, builds a pinned-cert TLS client config from
  the existing `--tls-cert` file and passes it to `run_coordinator_client`.
  Panics if `--coordinator-tls` is set without `--tls-cert`.
- `crates/sim-server/src/coordinator_client.rs`: `run_coordinator_client`
  now takes `Option<Arc<rustls::ClientConfig>>`. When `Some`, uses
  `tokio_tungstenite::connect_async_tls_with_config` with a `Connector::Rustls`;
  when `None`, plain `ws://` as before. Added `PinnedCertVerifier` (a
  custom `ServerCertVerifier` that accepts the server only if its leaf
  cert matches one of our pinned certs byte-for-byte). This is required
  because `openssl req -x509` generates a self-signed cert without
  `basicConstraints CA:TRUE`, which rustls's webpki rejects as
  `CaUsedAsEndEntity` when dropped into a `RootCertStore`. Cert pinning
  via exact match is both simpler and more appropriate for a single-cert
  mesh deployment. Added 3 unit tests (`coordinator_scheme_ws_when_tls_off`,
  `coordinator_scheme_wss_when_tls_on`, `build_coord_tls_config_rejects_missing_file`).

Coordinator side:
- `crates/coordinator/src/main.rs`: made the 7870 WS accept loop TLS-
  aware. When a `--tls-cert`/`--tls-key` pair is configured, wraps the
  accepted TCP stream via `TlsAcceptor::accept` before the WS handshake,
  so the 7870 port serves WSS. Generalized `handle_server_connection<S>`
  over `AsyncRead + AsyncWrite + Unpin + Send + 'static` so it can plug
  in either plain TCP or `tokio_rustls::server::TlsStream<TcpStream>`.
  Mac-local dev is unchanged — no `--tls-cert` means no acceptor means
  plain WS as before.

Deploy script:
- `start-unoq.sh`: appended `--coordinator-tls` to both the direct
  sim-server bootstrap invocations AND the `MESH_ARGS` environment
  passed to board-dash (so the dashboard's Start button also uses TLS
  on the boards).

Test scene tooling:
- `tools/test-suite/scenarios/peer-restart-reconvergence.ts`,
  `peer-restart-twice.ts`, `rebalance-stuck-recovery.ts`: hand-rolled
  `restartBoard` helpers updated to pass `--coordinator-tls` in the SSH
  nohup command. Without this, a restarted sim-server tried to speak
  plain WS to the new WSS coordinator, the handshake failed, and the
  tests timed out.

## Deviations

1. **WI-220 RequestSnapshot not removed.** The work item spec mentioned
   removing the client→server force-full path; I kept the
   `ClientMessage::RequestSnapshot` variant in the protocol enum
   (wire-stability + the server already ignores it at `systems/input.rs:264`)
   but deleted the handler that cleared the baseline. No client path
   produces it post-WI-220, so this is effectively dead. Can be removed
   later by a protocol-version bump.

2. **WI-223 pinned cert vs root-CA.** The WI spec suggested constructing
   a `RootCertStore` with the cert file. This fails for operator-
   generated self-signed certs (missing `basicConstraints CA:TRUE`);
   rustls rejects with `CaUsedAsEndEntity`. I implemented a custom
   `PinnedCertVerifier` that checks leaf-cert byte equality. This is
   stricter than CA-chain trust (we accept EXACTLY the cert at
   --tls-cert, not anything it signs) and matches the single-cert UNO Q
   deployment model.

3. **WI-223 scene-test helpers.** Three scene tests had their own
   `restartBoard` SSH helpers that reconstructed the sim-server
   command line. I updated all three to include `--coordinator-tls`
   alongside the existing `--tls-cert`/`--tls-key`. Without this, the
   Batch 6 coordinator (now WSS on 7870) was unreachable from
   restarted sim-servers during the tests.

4. **WI-221 pre-seed of empty entries.** The single-pass refactor
   initially skipped inserting `per_peer[peer_id]` when no entity
   matched; 4 existing tests index-accessed `per_peer[&peer_id]` and
   panicked. Added a pre-seed loop that inserts an empty vec for every
   shadowed peer with valid bounds, preserving the pre-refactor
   invariant. Documented inline.

5. **peer-restart-reconvergence flake NOT regression.** Observed
   occasional `shadow_count` swing exceeding the 5% tolerance on single
   runs. Five consecutive runs pass. Not a Batch 6 regression —
   appears to be pre-existing noise in the tolerance margin.
