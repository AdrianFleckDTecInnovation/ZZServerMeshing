# mesh-dev worklog 20260414-050031

## Task
Fix two bugs that prevent the mesh from self-recovering under load:

1. **Sim-server doesn't reconnect after coordinator drops it**: When the coordinator marks a server as dead (heartbeat timeout) and closes the WS, the sim-server needs to detect disconnect and reconnect, re-registering with the same server_id. The coordinator currently silently rejects duplicate registrations -- needs to accept re-registration when the old entry is dead.

2. **Heartbeat starvation under heavy rebalance load**: Processing large rebalance directives or peer list updates may delay heartbeat sends past the coordinator's 5-second timeout. Heartbeats need to be sent independently of message processing, and the timeout should be increased for safety.

## Changes Made

### Bug 1: Coordinator re-registration + stale disconnect protection

- `crates/coordinator/src/registry.rs` (`register()`): Changed from unconditionally rejecting duplicates to checking `reply_tx.is_closed()`. If the old connection's sender is closed (receiver dropped = connection dead), the entry is replaced with the new one. If the old connection is still alive, the duplicate is rejected as before.

- `crates/coordinator/src/registry.rs` (`unregister_if_sender_matches()`): New method that only removes a server entry if the given `reply_tx` is `same_channel()` as the stored one. This prevents a race condition where: (1) coordinator unregisters dead server, (2) sim-server reconnects and re-registers, (3) old connection's Disconnected event arrives and would incorrectly remove the new registration.

- `crates/coordinator/src/main.rs` (`RegistryEvent::Disconnected`): Added `reply_tx` field so the registry can verify which connection disconnected.

- `crates/coordinator/src/main.rs` (`handle_server_connection`): Passes `reply_tx.clone()` in the Disconnected event.

- `crates/coordinator/src/main.rs` (`run_registry`): Changed Disconnected handler from `reg.unregister()` to `reg.unregister_if_sender_matches()`. Recovery and peer list broadcast only happen if the entry was actually removed (i.e., it was the current connection, not a stale one).

- `crates/sim-server/src/coordinator_client.rs`: Enhanced reconnection log to include server_id for traceability.

### Bug 2: Heartbeat timeout increase

- `crates/coordinator/src/registry.rs` (`detect_dead_servers()`): Increased timeout from 5s to 15s. This gives servers much more headroom during heavy rebalance or peer list processing. The heartbeat sending architecture was already correct (separate `tokio::spawn` on a split WebSocket write half), so the main fix needed was just the timeout value.

### Analysis: Heartbeat architecture already correct

The sim-server's coordinator_client.rs already has the right architecture for heartbeat independence:
1. WebSocket is split into `ws_sink` (write) and `ws_stream` (read) via `futures_util::StreamExt::split()`
2. Heartbeat runs in a separate `tokio::spawn` task with its own `tokio::time::interval(1s)`, using `hb_sink` (the write half)
3. Message processing runs in the main task reading from `ws_stream` (the read half)
4. Since they're on separate halves of the socket, heartbeats are never blocked by message processing

No changes were needed to the heartbeat sending logic itself.
