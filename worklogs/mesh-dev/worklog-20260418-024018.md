# mesh-dev worklog 20260418-024018

## Task
Implement WI-144, WI-145, WI-146 from design 015 (shadow-tick-split):
split overloaded `Shadow.last_seen_tick` into `last_peer_tick` + `last_local_tick`
to fix cross-clock comparison bug that made S2-authoritative shadows flicker
on S1 when peers have different TickCounter uptimes.

### Live cluster — sustained shadow stability after deploy
Steady-state (no cross-clock):
```
S1 tick=735..903 shadow=30 auth=15     (15 samples over 7.5s, zero movement)
```

Cross-clock condition (restart S2 to induce large TickCounter skew):
- After S2 restart: S1 tick=1457, S2 tick=303, S3 tick=1438 — skew of 1150+ ticks, well beyond SHADOW_STALE_TICKS(300).
- 15 samples at 500ms intervals across the skew window:
```
S1:shadow=21..23 (swing=2)
S3:shadow=20..22 (swing=2)
```
- Pre-015 this would exhibit continuous oscillation as every S2 shadow despawned each tick then respawned on the next UDP packet. Post-015 the shadow count stays in a tight band with only natural rebalance drift.

Fully reconverged state (~25 s post-restart):
- S1: peer_health[2]={session=10334..., latest_tick=1023} — S2 at tick=1024 → 1-tick lag.
- S3: peer_health[2]={session=10334..., latest_tick=1024}.
- Both survivors' peer_health session_id matches S2's new boot session.
- chunk_evictions = 0 across the mesh.
