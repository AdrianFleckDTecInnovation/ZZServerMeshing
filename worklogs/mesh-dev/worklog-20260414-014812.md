# mesh-dev worklog 20260414-014812

## Task
Fix audit finding #049: `compute_delta` runs O(E) HashMap lookups per client before the fallback heuristic checks whether >80% of entities changed. When fallback fires (common -- all NPCs move every tick), the entire delta is computed and thrown away.

## Prior Work
- Session 20260414-011818: Implemented WI-020 through WI-024 (delta improvements, ACK wiring, ACK validation). 396 tests passing. The delta fallback was added in that session (WI-021), but the per-client redundant computation was not addressed.

## Plan
Add a `change_ratio` function to `delta.rs` that counts how many entities changed without allocating a Vec of updates. Use it in `systems.rs` before the per-client loop to compute a `force_full` flag. When `force_full` is true, skip `compute_delta` entirely in the per-client loop and go straight to the full snapshot path.

### Approach
1. Add `change_ratio(current, baseline) -> f32` to `delta.rs` -- iterates entities, counts changes via `entity_changed`, returns count/total. O(E) with zero allocation (just a counter).
2. Before the per-client loop in `prepare_client_snapshot`, find any client with a baseline and compute the change ratio once.
3. If ratio > DELTA_FALLBACK_THRESHOLD, set `force_full = true`.
4. In the per-client loop, when `force_full` is true and the client would otherwise enter the delta path, send the full snapshot directly (same as the existing fallback-full path).
5. Add tests for the new behavior (multi-client scenario where force_full skips all compute_delta calls).

### Files to modify
- `crates/sim-server/src/delta.rs` -- add `change_ratio` function + tests
- `crates/sim-server/src/systems.rs` -- add pre-loop probe, `force_full` flag

## Changes Made
- `crates/sim-server/src/delta.rs`: Added `change_ratio(current, baseline) -> f32` function. Iterates entities, counts new+changed via `entity_changed`, returns count/total. O(E) with zero allocation (just a u32 counter). Does not count removals since those are 16-byte UUIDs in the delta frame, not 47-byte entity records.
- `crates/sim-server/src/delta.rs`: Added 6 tests for `change_ratio`: empty_current, empty_baseline_all_new, no_changes, all_changed, partial (7/10), agrees_with_compute_delta (cross-validates against the full `compute_delta` output).
- `crates/sim-server/src/systems.rs`: Added pre-loop probe before the per-client iteration in `prepare_client_snapshot`. Finds any client with a baseline, calls `change_ratio` once, sets `force_full = true` if ratio > 0.80. When `force_full` is true, it is folded into the `send_full` condition, so clients skip the delta path entirely and go straight to the Arc-shared full snapshot.
- `crates/sim-server/src/systems.rs`: Added 3 tests: `force_full_skips_delta_for_all_clients` (3 clients, 10 entities all moved, all get 0x01), `force_full_not_triggered_when_below_threshold` (2 clients, 7/10 moved = 70%, both get 0x02), `force_full_no_clients_with_baseline_skips_probe` (new client, no baseline, probe returns false via unwrap_or).
