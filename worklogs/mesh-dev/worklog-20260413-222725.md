## Changes Made

### Finding #040: RemoveEntity during transfer forwards remove to target (HIGH)
- `crates/sim-server/src/systems.rs`: In the `RemoveEntity` handler within `process_client_inputs`, added a check for `TransferOutbound` before despawning. If the entity is mid-transfer, sends a `PeerMessage::ForwardedRemove` to `outbound.target_addr` via `OutboundForwards`. The target server already handles `ForwardedRemove` in `drain_inbound_events` (lines 249-270) and will despawn the entity. The entity is still despawned locally after the forward.

### Finding #033: Increase transfer retry count (HIGH, elevated)
- `crates/sim-server/src/systems.rs`: Changed `TRANSFER_MAX_RETRIES` from 1 to 3. This gives 4 total attempts (initial + 3 retries) over ~2 seconds. On WiFi with 5% packet loss, this reduces the probability of all ACKs being lost from ~0.25% to ~0.000006%.
- Updated `transfer_timeout_aborts_after_max_retries` test to use `TRANSFER_MAX_RETRIES` constant instead of hardcoded `1` for the retry_count setup.

### Finding #041: Heartbeat count excludes frozen entities (MEDIUM)
- `crates/sim-server/src/game_loop.rs`: Changed the heartbeat entity count query from `With<Authoritative>` to `(With<Authoritative>, Without<TransferOutbound>)`. Frozen entities no longer inflate the count sent to the coordinator.

### Finding #042: TransferOutbound entities visible in client snapshot (MEDIUM)
- `crates/sim-server/src/systems.rs`: Added a `transfer_query` parameter to `prepare_client_snapshot` that queries entities with `(With<Authoritative>, With<TransferOutbound>)`. These entities are included in the client snapshot with `authority_server` set to `ServerId(outbound.target_server)`. This eliminates the 1-3 tick visibility gap where the entity vanished from the source server's client view. Clients see the entity continuously -- it just changes authority color (server) smoothly.

### New tests
- `client_remove_during_transfer_forwards_to_target`: Verifies RemoveEntity for a mid-transfer entity sends ForwardedRemove to the target address and despawns locally
- `client_remove_without_transfer_does_not_forward`: Verifies normal RemoveEntity (no TransferOutbound) does not send any forwards
- `heartbeat_count_excludes_transfer_outbound`: Verifies the heartbeat count query excludes entities with TransferOutbound
- `client_snapshot_includes_transfer_outbound_with_target_authority`: Verifies transfer-outbound entities appear in the client snapshot with the target server's authority (parses the binary frame to check)
