- `crates/sim-server/src/receiver.rs`: Rewrote in-place.
  - `reassembly: HashMap<(u16, u64), ChunkReassembly>` -> `HashMap<(u16, u64, u64), ChunkReassembly>` keyed by `(server_id, session_id, tick)`. `ChunkReassembly` struct lifted to module scope so tests can construct it directly.
  - `latest_tick: HashMap<u16, u64>` -> `HashMap<(u16, u64), u64>` keyed by `(server_id, session_id)`.
  - Periodic global sweep (lines 118-148): composite-key lookup via `latest_tick.get(&(sid, ssid))`; same GLOBAL_STALE_TICKS=40 threshold; evictions still aggregated per `server_id` for `peer_health.chunk_evictions`.
  - MAX_REASSEMBLY_ENTRIES hard-cap eviction (lines 151-175): composite key; sort-by-tick (the `tick` component of the triple) preserves the oldest-tick-evicts-first semantics.
  - Inline sweep inside `ChunkedEntityUpdate` arm (lines 302-316): rekeyed by `(server_id, session_id)`; retain-filter preserves only this-(server,session)'s stale-free entries or entries from other (server,session) pairs.
  - All six `PeerMessage` match arms now extract `session_id` (was `session_id: _` from Batch 1).

### WI-134 (Session change detection + reset event)
- `crates/sim-server/src/resources.rs`:
  - Added `PeerSessionReset { server_id: ServerId, new_session_id: u64 }` struct with `#[derive(Debug, Clone, Copy)]` and an `#[allow(dead_code)]` note pointing at WI-135 (Batch 3) as the forthcoming consumer.
  - Added `peer_session_resets: Vec<PeerSessionReset>` field to `InboundQueue`.
  - Added `peer_session_resets.is_empty()` assertion to `resources_default_initialization` test.
- `crates/sim-server/src/receiver.rs`:
  - Added `session_of_peer: HashMap<u16, u64>` state in the receive loop.
  - Added `note_session` helper (7 args; at the clippy threshold so no new `too_many_arguments` warning): compares incoming `session_id` against stored session_of_peer entry, and on change:
    1. Logs at `info` via `tracing::info!(server_id, old_session_id=format_args!("0x{:016x}", prev), new_session_id=format_args!("0x{:016x}", session_id), "peer session changed — resetting receiver state")`.
    2. `reassembly.retain(|&(sid, ssid, _), _| !(sid == server_id && ssid == prev))`.
    3. `latest_tick.remove(&(server_id, prev))`.
    4. Clears `peer_health.latest_tick/packets_received/chunk_evictions` entries for that `server_id`.
    5. Pushes a `PeerSessionReset { server_id: ServerId(server_id), new_session_id: session_id }` onto the shared `InboundQueue.peer_session_resets`.
    6. Updates `session_of_peer.insert(server_id, session_id)`.
  - On the first-ever packet from an unknown `server_id`: no reset is emitted; only the `session_of_peer` insert happens.
  - `note_session` is called from every arm that carries a server_id: `EntityStateUpdate` (uses `server_id`), `ChunkedEntityUpdate` (uses `server_id`), and `AuthorityTransfer` (uses `from_server`). `ForwardedInput`, `ForwardedRemove`, and `TransferAck` do NOT carry a `server_id` in their payload; a brief code comment documents why these arms don't call `note_session`.

### New tests (all in `receiver::tests`)
1. `reassembly_completes_normally_for_single_session_across_ticks` — two ticks of a stable session reassemble cleanly, latest_tick advances, no reset event emitted.
2. `old_session_reassembly_entries_are_dropped_on_new_session_packet` — seeds session A entries for server 2 + server 3, injects a session B packet for server 2; asserts only server 2 session A entries dropped and server 3 (different server, different session) is untouched.
3. `peer_session_reset_event_pushed_exactly_once_per_detected_change` — verifies (a) first-ever packet emits no reset, (b) same-session packets emit no reset, (c) session change emits exactly one reset, (d) further same-session packets add no more resets. Asserts event's `server_id` and `new_session_id` fields.
4. `first_packet_from_new_server_id_does_not_emit_reset` — isolates the unknown-peer case: exactly the behavior required by the batch spec.
5. `session_change_clears_peer_health_counters_for_that_server` — confirms `peer_health` clearing is scoped to only the peer whose session changed; server 3's counters untouched.
6. `latest_tick_keyed_per_session_allows_independent_tracking` — direct HashMap sanity check that the composite key is actually sufficient to hold two sessions for the same server.

Test helper uses type aliases (`SessionOfPeer`, `ReassemblyMap`, `LatestTickMap`, `TestState`) to avoid the `clippy::type_complexity` warning on the 5-tuple return type.
