## Signal Flow (dead server detection -- new approach)
```
detect_dead_servers() returns [sid]
  -> reg.unregister(sid)
    -> reply_tx.send(Deregistered JSON)
    -> servers.remove(sid) drops ServerEntry (and reply_tx)
      -> sim-server receives Deregistered message
        -> breaks read loop
          -> hb_task.abort()
            -> "Lost coordinator connection" log
              -> 2s sleep -> reconnects -> re-registers
```

Defense-in-depth (if Deregistered never arrives):
```
sim-server read loop times out after 30s of silence
  -> breaks read loop -> same reconnection path
```

## Design Rationale
The AbortHandle approach was problematic because `tokio::task::abort()` cancels the task at the next `.await` point without performing any I/O cleanup. The underlying TCP socket is just abandoned -- no FIN packet is sent, no WebSocket close frame. The sim-server's read half blocks forever on `ws_stream.next()` because the kernel doesn't know the connection is dead (no RST either, since the socket is dropped without close()).

The Deregistered message approach is better because:
1. It uses the existing mpsc channel (reply_tx) which is already proven to work
2. The sim-server receives an explicit signal and can break cleanly
3. Even if the message doesn't arrive, the 30-second read timeout catches it
4. No dependency on OS-level TCP behavior or tokio task cancellation semantics
5. Simpler code -- no oneshot channel plumbing, no AbortHandle threading through the registry
