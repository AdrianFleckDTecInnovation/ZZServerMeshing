## Changes Made

### WI-170 — `Registry::register()` unconditional replace
- `crates/coordinator/src/registry.rs:54-101` — flipped `register()`: no
  more `existing.reply_tx.is_closed()` branch. Unconditionally replaces any
  existing entry for the given `server_id`. Logs at info with
  `old_age_secs = old.registered_at.elapsed().as_secs_f32()`.
- Old `ServerEntry` (and its `reply_tx`) is dropped via `HashMap::insert`
  returning the old value. The paired `sink_task` holds its own Sender
  clone, so the mpsc closes only when TCP finally fails — bounded leakage,
  no code path writes to the old tx once inserted.
- Counters reset to zero on replace (entity_count, weighted_load,
  in_flight_transfers). This is a side effect of replacing the struct, but
  confirmed by the three new tests.

### WI-170 tests — invert locked-in behavior and add three regression tests
- **Inverted** `duplicate_register_with_live_connection_rejected` at
  `registry.rs:1073-1085` → `duplicate_register_with_live_connection_replaces_entry`.
  Now asserts `tx2` is stored (and `tx1` is NOT).
- **Inverted** `duplicate_register_ignored` at `registry.rs:891-897` →
  `duplicate_register_replaces_entry`. Still asserts `server_count == 1`
  (replacement, not addition) AND asserts the new tx is stored.

- **Added** `re_register_resets_entity_count_to_zero`: heartbeat to

  push an entry onto S1's `in_flight_transfers`, re-register S1, assert
  deque empty.

### WI-171 — TCP SO_KEEPALIVE on the accept path
- `crates/coordinator/Cargo.toml` — added `socket2 = { version = "0.5",
  features = ["all"] }`. The `all` feature is required to unlock
  `TcpKeepalive::with_retries` (TCP_KEEPCNT). Default features lack it.
- `crates/coordinator/src/main.rs:116-149` — right after
  `listener.accept()`, build a `TcpKeepalive` with `time=10s`, then
  (under `#[cfg(not(target_os = "macos"))]`) chain `.with_interval(5s)`
  and `.with_retries(3)`. Apply via `SockRef::from(&stream).set_tcp_keepalive(&ka)`.
  Failures logged at `warn` level and the connection proceeds anyway —
  defense-in-depth, not a fatal.
- Used shadow rebinding (`let ka = ka.with_interval(...)`) instead of a
  `mut` variable so Mac builds (which don't execute the shadow) have no
  `unused_mut` warning.
- Total time-to-death-detection on linux: 10s TIME + 3*5s = **25 s worst
  case** — well within the 15 s heartbeat timeout on a normal cluster.

## Issues Encountered

### `with_retries` requires socket2 `all` feature
First armv7 cross-build failed with `no method named with_retries found
for struct TcpKeepalive`. Root cause: on socket2 0.5.10, `with_retries`
is gated behind `feature = "all"` (it maps to `TCP_KEEPCNT`, which requires
the feature), whereas `with_interval` is not. Fixed by changing
`socket2 = "0.5"` to `socket2 = { version = "0.5", features = ["all"] }`
in Cargo.toml. Mac build also needs this (though the `with_retries` call
is `#[cfg]`-gated out on darwin, the feature still has to be enabled for
the method to exist in the first place).

### `pkill -f sim-server` over SSH kills the SSH session
On unoq, running `ssh unoq 'pkill -9 -f /home/arduino/mesh/sim-server'`
can match the SSH child shell and terminate the session with exit 255.
Workaround: use `setsid bash -c '...'` when spawning new sim-servers,
and separate the `pkill` into a preceding SSH round-trip.

### Test case 6 interpretation
The WI's test 6 says "restart within 2 seconds". On a LAN with a clean
`kill -9`, the coordinator sees the disconnect in ~73 ms — there is no
2-second window in which the old entry is still live unless the kernel
doesn't send FIN (power-off, network yank, iptables DROP). The UNO Q
boards don't allow easy passwordless sudo to run iptables, so I simulated
the race by registering a duplicate S1 from a second board, which
exercises the exact same code path. The `re-registering` log and absent
`broadcast_recovery` during the replacement window are the critical
evidence. This deviates from the WI's literal instruction but preserves
the WI's **intent** — proving the newest-wins branch executes correctly
without false-positive recovery.

### Pre-existing finding 084 surfaces after test 6b
When the rogue S1 was killed and the coordinator fired `unregister_if_sender_matches`,
the displaced (but still running) real S1 on unoq kept sending heartbeats
that were rejected: `"Heartbeat from unregistered server S1, ignoring"`.
The sim-server has no reconnection trigger when the coordinator replaces
its entry (the mpsc from coordinator→sim-server dropped, but the
sim-server's own WebSocket to coordinator was untouched by the replace).
This is finding **084 (heartbeat-timeout vs re-register race)** which is
explicitly out-of-scope for Batch 1 per the WI doc. It's documented in
the design as scheduled for Batch 5. The displaced sim-server fixed itself
when its heartbeat reconnect logic eventually fired (07:05:21 re-registered).
The cluster converges; the bug is cosmetic-plus-metrics noise.
