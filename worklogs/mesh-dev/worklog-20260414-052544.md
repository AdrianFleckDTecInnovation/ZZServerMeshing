# mesh-dev worklog 20260414-052544

## Task
Fix the remaining reconnection issue: when `detect_dead_servers` fires in the coordinator, `reg.unregister(sid)` removes the registry entry but never closes the WebSocket connection. The sim-server keeps running, sending heartbeats that are silently ignored because the server_id is no longer in the registry. The reconnection loop never triggers.

## Prior Work
- Session 20260414-050031: Fixed re-registration (accept when old connection dead), stale disconnect protection (`unregister_if_sender_matches`), and heartbeat timeout increase (5s -> 15s). 458 tests passing.

## Root Cause Analysis
`handle_server_connection` creates `(reply_tx, reply_rx)`. It sends `reply_tx.clone()` to the registry via `RegistryEvent::Register`. The original `reply_tx` stays alive in `handle_server_connection`'s scope. When `unregister()` removes the `ServerEntry`, only the registry's clone is dropped -- the original clone in the connection task keeps the mpsc channel open, so `sink_task` keeps running, and the WebSocket stays open.

Dropping the registry's `reply_tx` clone alone cannot close the channel because `handle_server_connection` holds another clone. There is no way to reach into the connection task to drop it. The fix requires a mechanism to forcibly terminate the connection task from the outside.

## Solution: AbortHandle
Store a `tokio::task::AbortHandle` for each connection task in the `ServerEntry`. When `unregister()` removes an entry (called from the dead-server detection path), it calls `abort()` on the handle, which kills the `handle_server_connection` task, closing the WebSocket read stream, causing the sim-server to detect disconnect and trigger its reconnection loop.

The abort handle is plumbed from the accept loop to the registry via a oneshot channel: the accept loop spawns the task, gets the `JoinHandle`, extracts the `AbortHandle`, and sends it to the task via a oneshot. The task receives it and includes it in the `Register` event.

## Changes Made

### `crates/coordinator/src/registry.rs`
- **ServerEntry**: Added `connection_abort: Option<AbortHandle>` field with doc comment explaining its purpose
- **register()**: New parameter `connection_abort: Option<AbortHandle>`, stored in the entry
- **unregister()**: Now calls `abort.abort()` on the stored handle when removing an entry, forcing the WebSocket closed
- **unregister_if_sender_matches()**: Also calls `abort()` when removing (safe no-op since the task has already exited in the normal disconnect path)
- **heartbeat()**: Added warning log when heartbeat arrives from an unregistered server: "Heartbeat from unregistered server S{id}, ignoring"
- **Tests**: Added 3 new tests:
  - `unregister_aborts_connection_task` -- spawns a real tokio task, registers with its AbortHandle, verifies unregister kills it
  - `unregister_without_abort_handle_is_safe` -- verifies backward compatibility when no abort handle is stored
  - `heartbeat_from_unregistered_server_is_noop` -- verifies no panic when heartbeat arrives for unknown server
- Updated all 18 existing test `register()` calls to include `None` for the new `connection_abort` parameter

### `crates/coordinator/src/main.rs`
- **RegistryEvent::Register**: Added `connection_abort: Option<tokio::task::AbortHandle>` field
- **Accept loop**: Creates a `tokio::sync::oneshot` channel. Spawns `handle_server_connection` with the receiver. Sends `handle.abort_handle()` via the oneshot sender.
- **handle_server_connection**: New parameter `abort_rx`. Awaits the oneshot to receive its own AbortHandle. Includes it in the Register event as `connection_abort: connection_abort.clone()`.
- **run_registry Register handler**: Passes `connection_abort` through to `reg.register()`.

## Signal Flow (dead server detection)
```
detect_dead_servers() returns [sid]
  -> reg.unregister(sid)
    -> servers.remove(sid) returns ServerEntry
    -> entry.connection_abort.abort()
      -> handle_server_connection task is killed
        -> ws_stream read loop exits
          -> WebSocket closes
            -> sim-server detects disconnect
              -> reconnection loop fires
                -> re-registers with coordinator
```
